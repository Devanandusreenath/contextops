# Cypher queries used by ContextOps

> Generated by `python -m scripts.gen_cypher_docs` from `backend/app/graph/queries.py`. The example results below were produced by running each query against a freshly seeded graph after one investigation. Nothing here is hand-written output.

All queries are **named, parameterised** and executed only from `GraphRepository`. There is no endpoint or tool that executes user- or LLM-supplied Cypher. Read queries use `ro_query`. The only values interpolated into query text are labels / relationship types (validated against allow-lists) and a traversal depth (clamped to an integer 1..6).

## Graph — nodes
`Q_GRAPH_NODES`

**Purpose:** Load all entities the UI can render.  
**Expected result:** One row per node: the node and its first label.  
**Example parameters:** `{"labels": ["Service", "Pipeline", "Dataset", "Incident", "Person", "Team", "Project", "Decision", "Document", "Fix", "VerificationTest"]}`

```cypher
MATCH (n) WHERE labels(n)[0] IN $labels
RETURN n, labels(n)[0] AS label
```

**Example result (29 row(s); first 2 shown):**

```json
[[{"node": "Service", "id": "svc-gateway"}, "Service"], [{"node": "Service", "id": "svc-event"}, "Service"]]
```

## Graph — edges
`Q_GRAPH_EDGES`

**Purpose:** Load relationships whose two endpoints are both visible; preserves relationship ids and direction.  
**Expected result:** One row per relationship with src/dst ids and type.  
**Example parameters:** `{"labels": ["Service", "Pipeline", "Dataset", "Incident", "Person", "Team", "Project", "Decision", "Document", "Fix", "VerificationTest"]}`

```cypher
MATCH (a)-[r]->(b)
WHERE labels(a)[0] IN $labels AND labels(b)[0] IN $labels
RETURN r, a.id AS src, b.id AS dst, type(r) AS rtype
```

**Example result (41 row(s); first 2 shown):**

```json
[[{"rel": "e1"}, "svc-gateway", "svc-event", "DEPENDS_ON"], [{"rel": "e17"}, "svc-gateway", "team-platform", "OWNED_BY"]]
```

## Multi-hop dependency chain (variable length)
`q_dependency_chain(4)`

**Purpose:** Single-statement multi-hop traversal: everything `pipe-finance` transitively DEPENDS_ON. Depth is clamped to 1..6 before interpolation.  
**Expected result:** One row per path: ordered node ids and relationship ids.  
**Example parameters:** `{"id": "pipe-finance"}`

```cypher
MATCH p = (a {id: $id})-[:DEPENDS_ON*1..4]->(b)
RETURN [n IN nodes(p) | n.id] AS node_ids, [r IN relationships(p) | r.id] AS rel_ids
```

**Example result (2 row(s); first 2 shown):**

```json
[[["pipe-finance", "svc-normalizer"], ["e5"]], [["pipe-finance", "svc-normalizer", "svc-event"], ["e5", "e3"]]]
```

## Upstream hop
`Q_UPSTREAM_HOP`

**Purpose:** One bounded BFS hop upstream over DEPENDS_ON / PRODUCES (reverse) / CONSUMES. The repository repeats it up to the depth limit.  
**Expected result:** frm, nxt, rel id, relationship type.  
**Example parameters:** `{"ids": ["rep-finance"]}`

```cypher
MATCH (x)-[r:DEPENDS_ON]->(y) WHERE x.id IN $ids
RETURN x.id AS frm, y.id AS nxt, r.id AS rel, type(r) AS rtype
UNION
MATCH (p)-[r:PRODUCES]->(x) WHERE x.id IN $ids
RETURN x.id AS frm, p.id AS nxt, r.id AS rel, type(r) AS rtype
UNION
MATCH (x)-[r:CONSUMES]->(y) WHERE x.id IN $ids
RETURN x.id AS frm, y.id AS nxt, r.id AS rel, type(r) AS rtype
```

**Example result (1 row(s); first 2 shown):**

```json
[["rep-finance", "ds-billing", "e7", "DEPENDS_ON"]]
```

## Impact hop (blast radius)
`Q_IMPACT_HOP`

**Purpose:** One bounded BFS hop downstream: who is exposed if the given nodes fail (X DEPENDS_ON Y → Y reaches X; Y PRODUCES D → Y reaches D; X CONSUMES Y → Y reaches X).  
**Expected result:** frm, nxt, rel id, relationship type.  
**Example parameters:** `{"ids": ["svc-event"]}`

```cypher
MATCH (d)-[r:DEPENDS_ON]->(s) WHERE s.id IN $ids
RETURN s.id AS frm, d.id AS nxt, r.id AS rel, type(r) AS rtype
UNION
MATCH (s)-[r:PRODUCES]->(d) WHERE s.id IN $ids
RETURN s.id AS frm, d.id AS nxt, r.id AS rel, type(r) AS rtype
UNION
MATCH (d)-[r:CONSUMES]->(s) WHERE s.id IN $ids
RETURN s.id AS frm, d.id AS nxt, r.id AS rel, type(r) AS rtype
```

**Example result (3 row(s); first 2 shown):**


## Related incidents
`Q_RELATED_INCIDENTS`

**Purpose:** Earlier incidents that AFFECTED entities in scope, with their resolution and any curated SIMILAR_TO link.  
**Expected result:** incident, shared entity ids, fix id, similar-link count.  
**Example parameters:** `{"scope": ["svc-normalizer", "pipe-finance", "svc-event"], "current": "inc-2041"}`

```cypher
MATCH (s)-[:AFFECTED_BY]->(i:Incident)
WHERE s.id IN $scope AND i.id <> $current
WITH i, collect(DISTINCT s.id) AS shared
OPTIONAL MATCH (i)-[:RESOLVED_BY]->(f:Fix)
OPTIONAL MATCH (i)-[sim:SIMILAR_TO]-(c:Incident {id: $current})
RETURN i, shared, f.id AS fix_id, count(sim) AS similar_links
```

**Example result (2 row(s); first 2 shown):**

## Stale memory (Context Drift Guard)
`Q_STALE_MEMORY`

**Purpose:** A memory is potentially stale when anything it is about, or that its subject transitively DEPENDS_ON (0..3 hops), has a documented change newer than the memory's valid_from.  
**Expected result:** memory id, changed service, change document, timestamps.  
**Example parameters:** `{}`

```cypher
MATCH (m:Memory)-[:RELATES_TO]->(x)
WHERE m.kind IN ['Verified resolution', 'Observation', 'Knowledge conflict']
  AND m.validity_status IN ['valid', 'verified']
MATCH (x)-[:DEPENDS_ON*0..3]->(s:Service)<-[:DOCUMENTS]-(d:Document)
WHERE d.effective_at IS NOT NULL AND d.effective_at > m.valid_from
RETURN DISTINCT m.id AS memory_id, s.id AS service_id, d.id AS doc_id,
       d.effective_at AS changed_at, m.valid_from AS valid_from
```

# Write statements

## Upsert node (template)
Label is validated against `NODE_LABELS` before interpolation; properties are a bound map.

```cypher
MERGE (n:Service {id: $id}) SET n += $props RETURN n.id AS id
```

## Seed node (template)
Static properties refreshed; runtime-mutable properties only set on CREATE, so restarts never clobber agent state.

```cypher
MERGE (n:Service {id: $id}) ON CREATE SET n += $mutable SET n += $static RETURN n.id AS id
```

## Upsert relationship (template)
Type validated against `REL_TYPES`; MERGE on the relationship `id` makes it idempotent.

```cypher
MATCH (a {id: $src}), (b {id: $dst}) MERGE (a)-[r:DEPENDS_ON {id: $rid}]->(b) SET r += $props RETURN r.id AS id
```

## Set properties
Used for test results, fix verification status, memory validity and drift flags.

```cypher
MATCH (n {id: $id}) SET n += $props RETURN n.id AS id
```

## Delete agent-generated data
Only run by `scripts/reset_graph.py --runs-only` after confirmation.

```cypher
MATCH (n) WHERE n.origin = 'agent' DETACH DELETE n
```
